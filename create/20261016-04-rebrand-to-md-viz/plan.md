# Plan: rebrand to md-viz

## Goal

Rename the project from md-insights to md-viz: the package scope, every user-facing name, and the wordmark. The wordmark's new look is chosen from a temporary variants card on the design board. The `.md` logo icon stays as it is.

## Scope

In:
- `@md-insights/*` -> `@md-viz/*` in every package.json, import, tsconfig/components.json alias and the lockfile; root package name `md-viz`.
- Text "md-insights" -> "md-viz" in titles, `AppHeader` titles, aria-labels, the OpenAPI title (`openapi.json` regenerated), the localStorage key, the temp dir prefix in a test, README, CLAUDE.md, `packages/api-client/README.md`.
- Wordmark text `md-viz` with new `-`, `v`, `z` glyphs, and a temporary "wordmark variants" card on the design board.
- Guidelines entry and logo section description updated to the chosen wordmark.

Out:
- `create/` history (logs, plans, summaries of earlier sessions) and `demo/` content stay untouched.
- The `.md` logo icon and favicons (no pixel change, so `favicon.test.ts` keeps passing; the new `m`/`d` glyphs are not redrawn unless the chosen variant needs it).
- Anything outside the repo (GitHub repo, SQLite file name).

## Technologies

Existing stack only: pnpm workspaces, TypeScript, React, Tailwind v4, Vitest, the repo's own pixel-glyph helpers (`layoutPixels`). No new dependencies.

## Repository structure

No new directories. A temporary `apps/design/src/sections/WordmarkVariants.tsx` is added and removed again once a variant is chosen (the chosen rendering goes into `packages/ui`).

## Files

Modify (rename scope and text):
- `package.json`, `apps/*/package.json`, `packages/*/package.json`: names and `@md-insights/*` dependencies
- `pnpm-lock.yaml`: regenerated by `pnpm install`
- `apps/*/tsconfig*.json`, `packages/ui/tsconfig.json`, `apps/web/components.json`, `packages/ui/components.json`: aliases and paths
- every `.ts`/`.tsx`/`.css` importing `@md-insights/...` (apps/web, apps/design, apps/electron, apps/cache, packages/api-client, packages/ui tests)
- `apps/web/index.html`, `apps/design/index.html`, `apps/electron/src/renderer/index.html`, `apps/electron/src/main/index.ts`, `apps/web/src/App.tsx`, `apps/design/src/App.tsx`, `apps/design/src/sections/Components.tsx`, `apps/electron/src/renderer/src/App.tsx`: titles
- `apps/design/src/theme.ts` and `apps/design/tests/App.test.tsx`: storage key `md-viz-design-theme`
- `apps/cache/src/openapi.ts`, `apps/cache/openapi.json`, `apps/cache/tests/openapi.test.ts`: API title (run `pnpm openapi`)
- `apps/web/tests/App.test.tsx`, `apps/electron/tests/renderer/App.test.tsx`, `apps/electron/tests/main/scan.test.ts`, `packages/ui/tests/logo.test.tsx`, `packages/ui/tests/wordmark.test.tsx`: expectations
- `README.md`, `CLAUDE.md`, `packages/api-client/README.md`: names and descriptions

Wordmark:
- `packages/ui/src/lib/pixel-glyphs.ts`: add `-`, `v`, `z` glyphs (and any block-style helper the chosen variant needs)
- `packages/ui/src/components/wordmark.tsx`: new text, aria-label, rendering of the chosen variant
- `packages/ui/src/components/logo.tsx`: aria-label only
- `apps/design/src/sections/WordmarkVariants.tsx` (temporary), `apps/design/src/sections/Logo.tsx`: glyph sheet and description
- `apps/design/src/sections/Guidelines.tsx`: "pixel logo" rule updated to the chosen style
- `packages/ui/tests/wordmark.test.tsx`: updated for the new layout

## Steps

1. Rename the scope and names: sed `@md-insights/` -> `@md-viz/` and `md-insights` -> `md-viz` outside `create/`, `demo/`, the lockfile and generated code; fix the wordmark/logo text by hand afterwards (step 4).
2. Run `pnpm install` to relink the workspace and rewrite the lockfile; `pnpm generate`, then `pnpm openapi`.
3. Run typecheck and tests to confirm the mechanical rename is green (wordmark tests may fail until step 4).
4. Add the `-`, `v`, `z` glyphs and switch the wordmark to `md-viz` in a plain version.
5. Add the temporary "wordmark variants" card on the design board: 3-4 candidates varying block style (plain, hatched/outlined blocks on a same-size grid, subdivided mini-grid blocks) and accent placement (none, hyphen, `viz`, dot), each in light and dark.
6. Pause: the user picks a variant (or asks for adjustments).
7. Implement the chosen variant in `Wordmark`, delete `WordmarkVariants.tsx`, update `Logo.tsx` section text, the guidelines rule and the wordmark tests.
8. Update README.md, CLAUDE.md (project name, any mention of the wordmark style).
9. Run `pnpm format`, `pnpm lint`, `pnpm typecheck`, `pnpm test`; check the design board and web app in the browser.

## Open questions / risks

- Final wordmark style and accent placement are decided in step 6.
- The mockup the user shared was only an idea; the variants card will include a hatched/outlined version as one candidate.
- Renaming the localStorage key resets the saved design-board theme once.
- `pnpm install` after the rename needs network only if the lockfile cannot be rewritten offline; no dependency versions change.
- A blanket sed could touch generated or historical files, so it excludes `create/`, `demo/`, `node_modules`, and `src/generated`.
